# Supabase

Supabase-specific migration files that mirror the Prisma migration history.

## Why two sets of migrations?

Prisma manages the schema definition and generates a migration history under `prisma/migrations/`. Supabase tracks its own applied-migration state in a separate table. The `scripts/migrate.sh` script keeps both in sync automatically — running `bun run migrate <name>` generates the Prisma migration, copies the SQL into `supabase/migrations/`, and pushes it to Supabase.

## Directory

```
supabase/
└── migrations/    # Timestamped SQL files registered with Supabase
```

These files are generated by `scripts/migrate.sh`. Do not edit them manually.
